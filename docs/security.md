# Модель загроз і засоби захисту IIoT-системи

## 1. Мета

Забезпечити захист телеметрії насосної станції від несанкціонованого доступу, зміни повідомлень і повторного надсилання даних.

## 2. Модель загроз STRIDE

| Загроза | Приклад | Засіб захисту |
|---|---|---|
| Spoofing | Підключення від чужого імені | MQTT-автентифікація |
| Tampering | Зміна показників насоса | HMAC-SHA256 |
| Repudiation | Заперечення виконаних дій | Журналювання подій |
| Information Disclosure | Несанкціоноване читання даних | ACL |
| Denial of Service | Переривання роботи брокера | Reconnect, буферизація |
| Elevation of Privilege | Доступ до чужих топіків | Розмежування прав ACL |

## 3. Автентифікація

Для MQTT-брокера Mosquitto використовуються окремі облікові записи насосів і серверних компонентів.

Анонімне підключення заборонено. Паролі зберігаються у файлі `passwd` у вигляді хешів.

## 4. Контроль доступу

ACL обмежує можливість публікації повідомлень кожного пристрою власними топіками.

Сервіс ingest має право читати телеметрію, а сервіс alerts — читати телеметрію та публікувати аварійні сповіщення.

## 5. Криптографічний підпис

Для захисту цілісності повідомлень використовується алгоритм HMAC-SHA256.

Підпис обчислюється на основі MQTT-топіка, часу, nonce та JSON-повідомлення.

У разі зміни даних перевірка підпису завершується помилкою `InvalidSignature`.

## 6. Захист від повторного надсилання

Механізм NonceCache відстежує вже використані ідентифікатори повідомлень.

Повторне надсилання в межах часу зберігання кешу викликає `ReplayError`.

Повідомлення, час яких виходить за допустимі межі, відхиляються через `ExpiredError`.

## 7. Відновлення зв'язку

Після розриву MQTT-з'єднання шлюз переходить у режим накопичення телеметрії. Після відновлення зв'язку система намагається передати накопичені дані.

Застосовуються повторні спроби підключення зі збільшенням затримки.

## 8. Обмеження та подальше вдосконалення

У навчальному проєкті MQTT працює без TLS, тому HMAC захищає цілісність повідомлень, але не забезпечує їх конфіденційність під час передавання.

Для промислового використання додатково необхідні TLS, керування ключами, захищене зберігання секретів, централізоване журналювання, резервне копіювання та моніторинг безпеки.
