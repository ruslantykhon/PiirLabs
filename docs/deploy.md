# Інструкція з розгортання IIoT-системи

## 1. Необхідне програмне забезпечення

Для запуску системи використовуються:

- Windows 11;
- Python 3.12;
- Docker Desktop;
- Docker Compose;
- Git;
- PyCharm.

## 2. Підготовка

Необхідно відкрити репозиторій `PiirLabs` та перейти до папки `deploy`.

Перед запуском потрібно переконатися, що Docker Desktop працює, а порт 1883 не зайнятий іншою програмою.

## 3. Налаштування змінних середовища

На основі `.env.example` створюється файл `.env`.

У ньому задаються параметри підключення MQTT, паролі користувачів та спільний ключ SIGNING_KEY.

Реальні паролі та ключі не повинні зберігатися в GitHub.

## 4. Налаштування Mosquitto

Необхідно створити файл `passwd` з обліковими записами `pump-01`, `pump-02`, `ingest` і `alerts`.

Далі запускається генерація ACL:

```powershell
python -m deploy.gen_acl
```

Цю команду слід виконувати з кореня репозиторію.

## 5. Запуск системи

Перейти до папки `deploy`:

```powershell
cd deploy
```

Запустити всі контейнери:

```powershell
docker compose up --build -d
```

Перевірити їхній стан:

```powershell
docker compose ps
```

## 6. Перевірка роботи

Перегляд логів шлюзів:

```powershell
docker compose logs --tail=20 gateway1 gateway2
```

Перегляд запису даних:

```powershell
docker compose logs --tail=20 ingest
```

Перегляд сповіщень:

```powershell
docker compose logs -f alerts
```

Після імітації несправності повинна виникнути подія `raised` для насоса `pump-01`.

## 7. Перевірка бази даних

База SQLite розміщується за шляхом `/data/iiot.db` усередині контейнера ingest.

Для перевірки використовується SQL-запит:

```sql
SELECT COUNT(*) FROM telemetry;
```

Критерієм успішної роботи є збереження щонайменше 20 рядків.

## 8. Зупинка системи

Для зупинки контейнерів:

```powershell
docker compose down
```

Для повторного запуску:

```powershell
docker compose up -d
```

Іменовані Docker-томи дозволяють зберігати базу даних після зупинки та повторного створення контейнерів.

## 9. Можливі проблеми

Якщо Docker не запускається, необхідно перевірити стан Docker Desktop.

Якщо порт 1883 зайнятий, потрібно зупинити локальну службу Mosquitto.

Якщо MQTT-клієнт не підключається, слід перевірити паролі, конфігурацію брокера та ACL.

Якщо немає телеметрії, потрібно переглянути логи gateway та ingest, а також переконатися, що всі сервіси використовують однаковий ключ підпису.

## 10. Результат

Після успішного розгортання система забезпечує генерацію телеметрії двох насосів, її передавання через MQTT, запис у SQLite та формування аварійних сповіщень.
