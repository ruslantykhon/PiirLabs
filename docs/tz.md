# ТЗ: IIoT-моніторинг насосної станції

## 1. Мета
Система збирає телеметрію насосного агрегату, зберігає її та сповіщає оператора про відхилення, щоб виявляти знос до аварії.

## 2. Межі системи
Входить: симулятор/збір телеметрії, передача, зберігання, виявлення аномалій, дашборд.

Не входить: керування насосом, білінг, інтеграція з ERP.

## 3. Функціональні вимоги
- FR-1: Агрегат видає вимірювання щонайменше 1 раз на секунду.
- FR-2: Кожне повідомлення містить device_id, ts, running, metrics (4 метрики).
- FR-3: Тривога, якщо вібрація > 4,5 мм/с довше 10 с.
- FR-4: Історія зберігається не менше 30 днів.
- FR-5: Оператор бачить поточний стан агрегату на дашборді.

## 4. Нефункціональні вимоги
- NFR-1: Затримка від вимірювання до відображення ≤ 2 с (p95).
- NFR-2: Доступність сервера ≥ 99,5 % на місяць.
- NFR-3: Втрата даних при розриві зв'язку до 10 хв — 0 % (буфер на edge).
- NFR-4: Вузол обробляє ≥ 100 повідомлень/с.
- NFR-5: Однаковий seed дає однакову послідовність (відтворюваність тестів).

## 5. Інтерфейси
Формат повідомлення (JSON):

```json
{"device_id": "pump-01", "ts": 1760000000.0, "running": true,
 "metrics": {"vibration_mm_s": 1.84, "temperature_c": 55.2,
             "pressure_bar": 4.19, "current_a": 12.1}}
```

Одиниці: мм/с, °C, бар, А; ts — Unix-секунди.

## 6. Критерії приймання
- Усі тести `tests/test_lab1_sim.py` зелені.
- `inject_fault("bearing")` піднімає wear до ≥ 0,7 і збільшує вібрацію.
- При `running=False` тиск і струм дорівнюють 0.
- Два симулятори з однаковим seed дають однакові дані.

## 7. Інтеграція та розгортання системи

Для об'єднання компонентів IIoT-системи використовується Docker Compose. Система складається з MQTT-брокера Mosquitto, двох шлюзів насосних агрегатів, сервісу збереження телеметрії та сервісу аварійних сповіщень.

Шлюзи генерують телеметрію та передають її через MQTT. Сервіс ingest забезпечує збереження показників у SQLite, а сервіс alerts аналізує отримані дані та формує повідомлення про несправності.
Для захисту передбачено автентифікацію користувачів, розмежування доступу ACL та криптографічний підпис HMAC-SHA256. Реалізовано механізм повторного підключення після втрати зв'язку.

Розгортання здійснюється командою `docker compose up --build -d`. Стан компонентів контролюється за допомогою Docker healthcheck.

Критеріями приймання інтегрованої системи є успішний запуск усіх сервісів, передавання телеметрії від двох насосів, накопичення не менше 20 рядків у базі даних та формування аварійного сповіщення `raised` після імітації несправності.
